# CryptoAnalysis (CA) — 加密货币永续合约基本面分析技能

## 描述
从加密货币交易分析师的视角，基于**14维度评估框架**，对给定的 Binance USDT-M 永续合约品种进行系统性基本面+链上分析，输出多空研判的综合打分（0-1之间）。

## 触发场景
- 用户要求对某个加密币种USDT永续合约进行基本面分析、多空研判、综合评估
- 用户提到"加密分析"、"币种评估"、"永续合约分析"、"多空打分"等关键词
- 日程触发（标题含"加密基本面分析"或"CryptoAnalysis"）

## 绝对时间基准（每次执行前必须强制执行）

当前系统时间为：`{{CURRENT_DATETIME_UTC}}`（精确到分钟）。

所有时间相关的窗口期需根据数据类型差异化处理：
- **实时数据**（价格、资金费率、OI）：4小时窗口
- **日度数据**（现货价格、技术指标）：24小时窗口
- **周度数据**（链上数据、交易所余额）：7天窗口
- **月度数据**（宏观指标、加密周期数据）：30天窗口

## 分析评估步骤

### 第一步：信息和数据采集

收集每个维度需要的数据和信息。

**采集方法**：Binance API（优先）、CoinGecko API、web search、公开数据API。

**Binance API 优先策略**：

对于以下维度，优先使用 Binance API 获取实时/历史数据，失败时降级到 CoinGecko / web search：
- **维度9 资金费率**：Binance API 获取当前/历史资金费率
- **维度11 价格位置**：Binance K线计算均线/布林带/ATR
- **维度13 合约资金流**：Binance API 获取OI/多空比
- **维度14 期限结构**：Binance API 获取不同到期日合约价格

**全局要求**：

1. **时间精确性**：所有时间必须对应事件发生的具体情况，尽可能精确到分钟。若只能确定日期，需说明"仅能确定至日期"。

2. **来源可追溯**：信息来源必须写明可追溯来源（机构/媒体/交易所/链上平台/具体文章标题或URL）。

3. **禁止编造**：只基于可验证信息，严禁编造任何数字、事件或引语。如果没有搜索到任何可靠数据，必须在每个字段中如实体现，不得用常识或历史数据填充。

4. **固定输出格式**：每个子问题必须按以下格式输出5个字段，字段名和顺序不得变化：

```json
{
  "信息发生时间": "事件发生的具体时间（如2026-06-10 14:30 UTC），若无法精确到分钟则说明。该时间必须在窗口期内，否则标为历史背景",
  "信息来源": "...（必须列出本题检索得到的核心来源，至少1个；若完全没有找到，写"未检索到足够可信来源"）",
  "信息总结": "...（基于窗口期事实总结，若没有则写"未发现"）",
  "对市场的影响": "...（若没有显著影响则写"无直接可验证影响"，不可强行编造）",
  "这个信息能影响多久": "...（若没有则写"不适用"）"
}
```

5. **实时搜索优先**：每个子问题必须先执行实时信息搜索，再给出答案；严禁仅凭参数记忆或常识直接作答。

6. **数据留白原则**：对于数值类问题，如果搜索结果中没有窗口期内的精确数据，必须在"信息总结"中明确说"未在窗口期内检索到对应数据"，并说明不确定性。严禁用历史均值、线性外推或相似事件数据进行编造。

7. **一致性原则**：在分析过程中，引用的价格、关键时间点等必须自洽。如果发现不同问题引用了明显矛盾的价格，必须标注矛盾并注明各自来源的时间戳，优先采信时间戳最接近 `{{WINDOW_END_UTC}}` 的来源。

#### 各维度搜索指引

**维度1 - 全球流动性**：
- 搜索关键词：`Fed interest rate`、`FOMC minutes`、`Jerome Powell speech`、`DXY dollar index`、`real yield TIPS`
- 重点关注：利率决议、官员讲话、DXY走势（DXY跌=利多加密集）
- **数据窗口**：30天（宏观数据为月度发布）
- **推荐数据源**：FRED (fred.stlouisfed.org)、CME FedWatch

**维度2 - 地缘政治**：
- 搜索关键词：`geopolitical conflict`、`trade war`、`sanctions` + `Bitcoin safe haven`
- 重点关注：中东局势、俄乌冲突、中美贸易、BTC"数字黄金"叙事有效性
- **数据窗口**：4小时（实时）
- **注意**：区分"风险off"（利空BTC短期）和"货币崩溃"（利多BTC作为替代储值）两种影响路径

**维度3 - 监管政策**：
- 搜索关键词：`SEC crypto regulation`、`Bitcoin ETF flow`、`Ethereum ETF flow`、`crypto bill Congress`、`crypto ban`
- 重点关注：SEC执法行动、ETF净流入/流出、各国监管框架变化
- **数据窗口**：7天

**维度4 - 宏观数据**：
- 搜索关键词：`US CPI release`、`nonfarm payrolls`、`GDP`、`ISM PMI` + `latest`
- 重点关注：数据超预期/不及预期 → 利率预期 → BTC方向
- **数据窗口**：30天（月度数据）

**维度5 - 加密情绪**：

**维度6 - 宏观流动性**：

### 第三步：权重评估

考虑当前的时间和市场状态，评估目前每个维度的权重。

权重调整原则：

### 第四步：加权平均评估

根据上述各维度评分和各维度权重，进行加权平均得到综合得分。

$$综合得分 = \sum_{i=1}^{14} (得分_i \times 权重_i)$$

输出格式：

| ... | ... | ... | ... |

**多空研判解读**：

- 0.70 - 1.00：强利多，建议多头思路

### 第五步：操作方案生成

基于综合得分和关键维度数据，生成可操作的交易方案。

#### 5.1 方向判断

根据综合得分确定建议方向：
- 综合得分 ≥ 0.55：多头方向
- 综合得分 ≤ 0.45：空头方向
- 0.45 < 综合得分 < 0.55：观望

**多维度交叉确认**（必须满足至少2条才可开仓）：
- 综合得分方向与合约资金流（维度13）信号一致
- 综合得分方向与资金费率（维度9）信号一致
- 价格位置（维度11）支持该方向（如做多时价格在MA20上方）

#### 5.2 入场方案

| 项目 | 生成规则 |
|------|----------|
| 建议入场区间 | 维度11（价格位置）中的关键支撑位（做多）或阻力位（做空），取MA支撑/阻力、布林带上下轨 |
| 入场触发条件 | 价格触及入场区间 ± 1%范围 + 资金费率（维度9）方向确认 |
| 首次入场仓位 | 根据置信度确定：综合得分偏离0.5越远仓位越大，0.55-0.60建议0.3×，0.60-0.70建议0.3×，0.70+建议0.5×（空头同理） |

#### 5.3 止损方案

| 项目 | 生成规则 |
|------|----------|
| 止损价位 | 做多：维度11计算的MA支持线 - 1个ATR；做空：MA阻力线 + 1个ATR |
| 止损幅度 | 一般品种不超过5%，高波动品种（如小市值Meme）不超过8% |
| 止损后观察 | 评估是否为假突破，如资金费率未反转可考虑二次入场 |

#### 5.4 止盈与加仓

| 项目 | 生成规则 |
|------|----------|
| 第一目标位 | 做多：维度11计算的上方阻力位；做空：下方支撑位 |
| 第二目标位 | 结合维度14（期限结构）的极端分位数和维度9（资金费率）的历史均值回归位 |
| 加仓条件 | 盈利达到止损幅度的1.5倍后 + 合约资金流持续确认，加仓不超过首次仓位 |
| 移动止损 | 盈利达到第一目标后，止损移至成本价；达到第二目标后，止损移至第一目标位 |

#### 5.5 操作方案约束

- **中性区间不开仓**：综合得分在0.45-0.55时，仅输出观望建议
- **维度冲突降仓**：合约资金流/资金费率与综合得分方向冲突时，仓位减半
- **无数据不开仓**：维度11（技术结构）和维度13（合约资金流）均无Binance数据时，操作方案标注"数据不足，不建议开仓"
- **重大事件预警**：维度4（宏观数据）有CPI/NFP/FOMC等重大事件待发布时，标注"建议事件落地后再操作"
- **资金费率保护**：资金费率 > 0.1%（极端做多拥挤）时，做多仓位降半或不开启；资金费率 < -0.1%（极端做空拥挤）时，做空仓位降半或不开启
- **OI保护**：OI达到30日历史极值时标注"OI过热警告"

- 如果某个维度确实搜索不到任何窗口期信息，该维度默认评分为0.5（中性），权重适当降低
- 分析过程中发现不同来源数据矛盾时，必须标注矛盾并说明取舍依据
- 最终报告末尾必须附上免责声明：本分析仅供参考，不构成投资建议
- **窗口期差异化**：实时数据4h窗口、日度数据24h窗口、周度数据7天窗口、月度数据30天窗口
- 加密市场24/7交易，分析时需说明价格对应的UTC时间戳
